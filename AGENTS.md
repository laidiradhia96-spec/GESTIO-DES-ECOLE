# AGENTS.md

Laravel 12 school-management app ("pour manager une école"), French-language UI, running on XAMPP (Windows) + MySQL.

## Environment & commands
- DB is **MySQL** (`ecole`, root, no password) — set in `.env`, NOT the sqlite default from `.env.example`. Tests use sqlite `:memory:` via `phpunit.xml`.
- `php artisan db:show` fails on XAMPP with `performance_schema.session_status doesn't exist` — expected, NOT an app bug. Verify DB via `php artisan tinker --execute="..."` instead.
- Dev: `composer run dev` (concurrently runs `artisan serve`, queue, pail, vite). Assets: `npm run dev` / `npm run build` (Vite 7 + Tailwind).
- Tests: Pest. `composer test` = `config:clear` + `php artisan test`. 
- Migrations: 22 files, all ran. Do NOT run `migrate:fresh` blindly — see migration bug below.

## Known bugs / gotchas (verified)
- **`php artisan test` currently FAILS**: `database/migrations/2026_08_14_133003_add_subject_id_to_payments_and_payment_signalements_tables.php` uses raw MySQL `ALTER TABLE ... MODIFY ...` which breaks on sqlite `:memory:`. Needs a driver-agnostic rewrite to make tests pass.
- **`routes/web.php` points to missing controller methods**:
  - `payments.unpaid` → `PaymentController@unpaid` (method absent)
  - `payments.print` → `PaymentController@print` (method absent; view `payments/print.blade.php` exists)
  - Visiting either route → 500 "method not found".
- **`AttendanceController::store` (line ~172)**: uses `$student['id']` inside a loop whose variable is `$studentData` → "Undefined variable" crash on every attendance save. Also `createPaymentSignalement()` duplicates logic that `checkPaymentForAttendance()` already handles.
- Dead/stray files (unused, safe to remove):
  - `app/Models/createpaymentsignalments.php` (a migration accidentally placed in Models)
  - `app/Models/Session.php` — duplicate of `ClassSession.php` (the routed one); Session is never used
  - `app/Http/Controllers/Auth/UnpaidSignalementController.php` — never routed; references view `signalements.show` which doesn't exist
- `php artisan db:show` uses `performance_schema` — see above.

## Architecture notes
- Auth: Breeze. `admin` middleware alias registered in `bootstrap/app.php` (`AdminMiddleware` checks `user->role === 'admin'`). Routes: `/dashboard` (auth+verified), admin group uses `['auth','admin']`, student space at `/student/dashboard`.
- `User.role` is a plain string column ('admin' | 'student'); no roles package.
- Domain models: Student, Teacher, Subject, Enrollment, Payment, PaymentSignalement, Attendance, ClassSession, Announcement, Level, PaymentSchedule, UnpaidSignalement.
- Payments: `payments` table has `amount_due/amount_paid/remaining_amount` + `payment_type` (`monthly`|`vip`). Signalements auto-created from attendance/payments (see AttendanceController).
- **Level management is mid-migration**: `students.level` and `subjects.level` are free strings; a newer `levels` table + `teacher_level` pivot + `Level` model exist but are not yet wired into students/subjects. Don't assume they're in sync.
- Teachers↔Subjects via `subject_teacher` pivot (many-to-many); Enrollments link student+subject+teacher with `status` ('active') and `payment_type`.
- Views are blade under `resources/views`; controllers/DB columns are French, some code comments are Darija/Arabic. Keep that mix.

## Conventions
- French for UI strings; don't translate existing French text.
- Money columns are `decimal(10,2)`; Payment model casts to `decimal:2`.
- Dates cast to `date`; `payment_time` is a `time` string.
- Follow existing controller style: validation arrays + `$validated`, `DB::transaction` for multi-write operations, `back()`+`withErrors` for validation failures, `redirect()->route(...)->with('success', ...)`.

# Laravel 12

- CRITICAL: ALWAYS use `search-docs` tool for version-specific Laravel documentation and updated code examples.
- Since Laravel 11, Laravel has a new streamlined file structure which this project uses.

## Laravel 12 Structure

- In Laravel 12, middleware are no longer registered in `app/Http/Kernel.php`.
- Middleware are configured declaratively in `bootstrap/app.php` using `Application::configure()->withMiddleware()`.
- `bootstrap/app.php` is the file to register middleware, exceptions, and routing files.
- `bootstrap/providers.php` contains application specific service providers.
- The `app/Console/Kernel.php` file no longer exists; use `bootstrap/app.php` or `routes/console.php` for console configuration.
- Console commands in `app/Console/Commands/` are automatically available and do not require manual registration.

## Database

- When modifying a column, the migration must include all of the attributes that were previously defined on the column. Otherwise, they will be dropped and lost.

- Laravel 12 allows limiting eagerly loaded records natively, without external packages: `$query->latest()->limit(10);`.

### Models
